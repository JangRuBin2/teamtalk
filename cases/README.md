# 사건 파일 작성법

사내 추리의 사건 뼈대입니다. 범인, 알리바이, 단서, 증거 같은 **사실은 이 파일에서 고정**되고, 게임을 시작할 때마다 이름이 무작위로 채워지고 AI가 성격·말투·인간관계·팀장 브리핑만 새로 씁니다.

- 레포의 `cases/` 폴더에 넣으면 다음 빌드부터 게임에 포함됩니다.
- 빌드 없이 내 PC에서만 쓰려면 `~/.teamtalk/cases/` 폴더에 넣으세요. 바로 반영됩니다.
- 파일 형식이 틀리면 그 사건은 건너뜁니다.

## 자리표시

| 표시 | 바뀌는 것 |
|---|---|
| `{A}` ~ `{F}` | 용의자 이름 (`### A` 처럼 용의자 제목에 쓴 글자) |
| `{회사}` | 회사 이름 |
| `{팀장}` | 팀장 이름 (예: "박정훈 팀장") |

## 형식

````markdown
# 사건 제목

## 개요
무슨 일이 있었는지 사실만. AI가 팀장 브리핑을 쓸 때 참고합니다.

## 범인
B

## 동기
...

## 수법
...

## 결정적 모순
범인의 주장과 어떤 증거가 부딪히는지. 범인 AI는 이 부분을 찔리면 말이 꼬입니다.

## 타임라인
- 어제 19:40 - {A}가 ...
- 어제 19:52 - {B}가 ...

## 용의자

### A
- 직급: 대리
- 부서: 개발팀
- 성격 힌트: (선택) 성격 방향
- 주장: 남들에게 말하는 행적
- 실제: 진짜 행적
- 비밀: 사건과 무관하지만 숨기고 싶은 것 (수상해 보이게 하는 장치)
- 단서:
  - 이 사람이 알고 있는 것 1
  - 이 사람이 알고 있는 것 2

### B
...

## 증거

### 출입 기록
```
어제 19:52  {B}  입장
```
````

## 좋은 사건을 위한 규칙

- 용의자는 4~6명(5명 권장), 증거는 3개 이상(4~5개 권장).
- 범인을 가리키는 단서는 **최소 두 사람**에게 나눠 주세요. 한 명만 심문해서 풀리면 재미없습니다.
- 증거만으로 범인 이름이 바로 나오면 안 됩니다. 증언과 맞춰봐야 의미가 드러나게 하세요.
- 무고한 사람마다 비밀을 하나씩 주고, 증거 중 하나는 그 비밀을 건드리는 레드 헤링으로 쓰면 좋습니다.
- 결정적 모순은 "주장"과 "증거" 사이에 있어야 공정합니다.
